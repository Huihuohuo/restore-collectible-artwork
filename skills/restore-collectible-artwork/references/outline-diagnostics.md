# 四角、圆角与边缘诊断

在源照片四角难以目测、圆角可能带入外部环境时使用。依赖仍只有 NumPy/Pillow；这一步不调用生成工具，也不输出还原成品。

## 从粗四角得到可检查的候选

先看原图，确认目标对象和方向；geometry 记录已确认的对象、宽高、单位及本图粗四角 TL/TR/BR/BL。粗四角指四条直边延长线的交点，不是圆弧上的任意点。不复制其他照片的坐标。脚本沿粗边附近搜索连续直线，并细化交点；这是有目标提示的边缘辅助，不是从任意复杂照片中自动认出物品。

```sh
python scripts/inspect_geometry.py \
  --input source.jpg --geometry rough-geometry.json \
  --out-dir work/outline-check
```

输出：

- `source-edges.jpg`：源图粗四角（橙色）与候选边线（青色）。
- `corner-comparison.jpg`：四角的未遮罩实拍，以及同一图上叠加的共享圆角候选。
- `edge-comparison.jpg`：四条边中点放大图，检查纸边、阴影、反光和画内内容。
- `rectified-unmasked-with-context.png`：保留周围实拍环境的拉正图，不能当作去背景完成图。
- `report.json`：边线支持度、偏移、各角半径证据、分歧及搜索范围。
- `candidate-geometry.json`：待核对参数，带 `geometry_review` 标记。prepare 会拒绝未核对的候选。

助手先实际查看上述图片。修正有依据的问题后，把选定参数另存为本次 `geometry.json`，设置 `geometry_review: "accepted"`，再 prepare。不要求用户逐项批准技术参数，也不让用户测圆角；遇到照片确实看不清、物品范围无法确定等情况才说明缺失证据。

`--search-px` 是粗四边附近搜索的**源照片像素**范围，默认约源四边短边的 1.2%，不是向内裁切比例。结果达到搜索边界、支持不足或认到印刷边框时，先改粗四角/范围。已有核对过的四角可加 `--keep-quad`，仅在这组边界上测圆角；报告仍记录其他候选边线。报告中的像素单位不能混用。

## 同一物品的圆角怎么决定

测量基于**未加圆角遮罩的实拍**，寻找角部明暗/颜色边界。以拉正后的直边交点为原点，左上圆弧的圆心在 `(R, R)`，不是矩形顶点 `(0, 0)`；其余角对称。对照线调用与 prepare 完全相同的遮罩函数，避免画出的弧和实际裁切不一致。

四个角先分别估计，再选有连续边缘且半径相近的一组，合并这组证据拟合本物品的共享半径。遮挡、低对比、反光和不一致的角不直接参加算术平均；报告保留分歧。至少两角支持才给候选；证据不足时半径留空，不自动改用固定数值。分歧显著时，即使有两角一致，也必须检查其他角和直边定位。

`--max-radius-px` 是**输出像素**搜索上限，默认短边的 12%，不是输出圆角默认值。搜索命中上限说明还没找到可靠峰值。直角允许 0；拍立得独立画面窗口固定为矩形，不用此步骤推断外相框圆角。换输出分辨率时，半径也须按比例换算。

共享圆弧适合本来就是四角同形的平面物品。原物有异形角、折损、明显弯曲或无法用一个圆描述时，不强制对称、不裁掉证据；助手应检查后单独处理轮廓。曲线拟合不是语义识别，也不能仅靠梯度区分纸边、印刷线条与手指。

## 内缩另算，不设固定百分比

先确认直边定位到了什么：卡外桌面/肤色、投影、纸张厚度、表面亮棱，还是原画面的细线。可疑处沿边法向查看像素剖面；报告的边缘对比曲线仅辅助定位，并不能自动断言“亮棱宽 9 像素”。

只有实拍外部像素实际进入选定画面，才修正对应边界到足以排除它的位置。不同边允许不同修正；不因一个角有问题就缩小整张卡，也不把实拍反光全部靠裁边消除。改变四边后需重新检查圆角和边缘画面；不要缩完又拉伸来假装没有损失。原设计满版到边时尤其保守。

诊断默认内缩 0；不采用通用的 0.4%、9px 或统一圆角。数值自动结果均是候选，最终依据是原图与实际轮廓对照。
